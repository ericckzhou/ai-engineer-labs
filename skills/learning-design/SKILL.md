# Skill: Learning Design

**Type:** Method  
**Used by:** Teacher, Curriculum Designer

## Purpose

Structure explanations and projects so that understanding is built progressively,
from intuition to production-level depth.

## Teaching Sequence (Required)

For every new concept:
1. Motivation — why does this exist? what problem does it solve?
2. Intuition — ELI12 explanation with analogy
3. Technical depth — precise definition and mechanism
4. Guided example — minimal working case
5. Reflection — learner states understanding before building
6. Implementation — build something with it
7. Failure — break it and learn why
8. Evaluation — measure if it works
9. Connection — how does this relate to what came before and what comes next?

## Anti-patterns to Avoid

- Starting with terminology before intuition
- Skipping the "what breaks without it" question
- Presenting an implementation without explaining the design decisions
- Leaving concepts disconnected from each other

## Adaptation Rules

Read `memory/learner/skill-map.md` before designing an explanation.
- If the learner is advanced in a domain: compress intuition, expand technical depth
- If the learner has a documented misconception: address it explicitly, with the correct version
- If the learner struggled on a prior project: slow down, use more analogies
